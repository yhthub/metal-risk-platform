# NHANES v5 本地结局估计模型

## 范围

本地系统使用已训练完成的 `nhanes_12outcomes_targeted_20261016_005`，不重新训练，不修改阿里云或 YHT。每人一次输入可请求 12 个结局；模型适用性或输入条件不满足时，对应结局显示原因，不能编造数值。

本说明对应 `4.1-风险模型` 接入版本，描述本地验收状态，不是云端已发布回执。Git 只保存应用代码、公开示例及来源说明、测试与文档；`models/nhanes_v5` 推理包、训练/验证数据、用户上传表格、完整检索库及真实密钥不入 Git。克隆仓库后仍须独立准备模型资产；RAG 检索资产同样单独配置。

模型针对 NHANES 2009–2018 美国调查数据中的同期测量进行条件估计，不代表重金属的因果效应，不预测未来发病率，不用于个体诊断。时间验证已在研发阶段多次查看，属于探索性验证，不是外部临床验证。

## 独立运行环境

`backend/.venv-prediction` 为本项目独立环境，不复用或升级共享 Anaconda。XGBoost 3.4.1 要求 Python 3.12+；当前专属环境由本机已存在的 Python 3.12 创建。

Linux 训练包为 `xgboost-cpu==3.4.1`；Windows 使用官方 `xgboost==3.4.1` 同版本 wheel，推理明确限定 CPU。CatBoost 同为 `1.2.8`。完整后端与推理依赖由 `backend/requirements-prediction.txt` 声明。

新机器安装：

```powershell
py -3.12 -m venv backend/.venv-prediction
backend/.venv-prediction/Scripts/python.exe -m pip install --only-binary=:all: -r backend/requirements-prediction.txt
backend/.venv-prediction/Scripts/python.exe scripts/prepare-nhanes-local.py --smoke
```

开发启动脚本优先使用该专属环境。也可以明确指定 `OCC_HEALTH_PYTHON` 后运行项目的 `start-dev.bat`。不要为了运行本功能修改系统 Python、重装全局 Anaconda，或安装 GPU/CUDA 环境。

本机准备核验已完成：49 个资产哈希一致；24 个原生模型均在 Windows 的同版本 XGBoost/CatBoost 中加载并完成合成输入预测；未读取训练或测试 CSV、未调用 `fit`。核验回执为 `models/nhanes_v5/LOCAL_RUNTIME_SMOKE.json`。这仅验证运行兼容性，不是临床有效性验证。

## 输入与展示原则

基础模型使用年龄、BMI、性别、全血铅/镉/总汞及匹配定义的个人因素。**铅为 μg/dL；镉、总汞为 μg/L；均为全血。** 尿液、头发或化学形态不明的汞不能直接混入。缺失值保留为缺失，不能填写 0 代替未知。

中国教育分类不能未经确认自动视同美国 NHANES 学历；“吸烟/饮酒”也必须符合研究定义。模型输入映射与界面展示由后端统一处理，不接受客户端伪造的风险等级。

模型对基础输入的部分结局仍弱，系统默认沿用模型卡的可靠性保护：验证表现不达标时不展示数值，不为凑齐 12 个结局而放宽。输出单位、版本、适用条件、验证误差和非诊断提示应同时可见。

本次没有改动原型因果分析、干预建议、群体分析的科学含义；它们不得因接入预测模型而自动宣称已经完成临床验证。

## 本地体验入口

1. 双击项目根 `start-dev.bat`，脚本优先使用 `backend/.venv-prediction`，无需 GPU。
2. 打开 `http://127.0.0.1:3000/risk?mode=individual`。沿用仓库原“风险量化与预警”页面，选择已接入的 XGBoost / CatBoost 模型组，可用“一键合成示例”后点击“运行预警评估”。不再使用上一版替换原界面的新页面设计。
3. 或在数据工作台填写单人资料，生成画像后点击“携带当前数据进入风险分析”；原始单位保留，进入预测页通过“核对本次输入”弹窗确认全血、单位及分析物。
4. 计算后打开本次报告，可下载 CSV/JSON 或打印存为 PDF。修改输入会立即使旧结果失效；刷新页面后不保留个人报告。

一次响应含 12 项结局，当前基础输入版默认 7 项提供探索性估计；血清肌酐、尿素氮、尿白蛋白肌酐比、HbA1c、HDL 胆固醇因验证表现不足，显示原因但不提供数值。页面不是 12 项均可用的医疗预测产品。

群体入口为 `/risk?mode=batch`，提供“一键公开数据演示”和“一键预警案例演示”，均导入同一批20名真实 NHANES 2017–2018 公开成人，并对演示文件中的所有对象完成模型计算。普通演示预设综合相对预警阈值80分，预警演示预设75分；它们只改变可见的筛查规则，不改变输入或伪造预测结果。当前固定示例实测80分无人达到，75分有1人达到（1/20）；这不是预存风险标签或模型准确性指标。演示资产在既有300人公开样本上，按唯一 SEQN 一对一关联同周期原始 `BMX_J` 的真实 BMI，按编号选取字段完整的20人；不补造 BMI、不预存模型结果、不替换原300人描述性分析示例。界面与服务端保留样本来源、周期及局限：固定非随机子集、非职业人群、未加权展示，不能作为独立模型效果验证。

自己的文件仍从数据工作台导入。除原有导入字段外，真实模型还要求 `BMX_J__BMXBMI`，以及年龄、性别、全血铅、镉和总汞；旧的300人公开描述性分析示例不含 BMI，不能直接用来预测。不要猜测 BMI、不要用零填缺失。群体功能对整份上传文件的所有合格记录完成12项结局计算后，再返回全量排序、分布、均值/中位数/四分位数及性别/年龄分组描述。每行不合格原因保留，5项验证不足的结局仍不出值。表格前端分页只限制浏览，不限制计算和下载人数。内部512行向量块只是CPU和内存控制，不是抽样。固定演示资产的全血/分析物/原始单位由来源核验，不能据此自动确认用户自己文件的元数据。

预测接口为 `/api/risk/status`、`/demo`、`/demo-batch/import`（POST）、`/predict`、`/predict-cohort`（POST，整文件全量）。旧 `/predict-batch` 保留兼容，但新群体页不再通过分页API计算。`/predict-cohort` 请求仅 `{file_id,measurements}`，不接受offset/limit；只有整文件全部处理成功后才返回 `complete:true`、`analysis_scope:all_uploaded_records` 和完整records/summary，不能把部分页标成全群体。导入成功不等于模型计算成功。原模拟 `/assess`、`/high-risk/{id}`、`/detail/{id}`、`/report/{id}` 已返回 HTTP 410，不再生成固定患病概率。

## 原风险页面动态图表（2026-10-16纠偏）

前端设计恢复依据为 `yhthub/metal-risk-platform` 的历史提交 `8562f927088c604aec00af0085067aa6e03920e6`。只复用原前端风险分析页和报告页的布局、图卡、模型选择栏、纸张/水印/圆章及样式；没有回滚后端、整个前端或其他功能的既有改动。该历史提交不是本分支当前提交的声明。

`POST /api/risk/dashboard` 接受 `{input: 单人预测输入, target: 结局标识}`，返回本次12项预测及所选结局的原生SHAP、16点全血铅输入响应、5×5全血铅/镉联合输入响应。

群体页将“特异性高危易感人群预警榜”和“高危预警对象人群占比”合并为一张占整行的大卡，左右虚线分隔。榜单仅展示达到综合阈值的对象Top10/20，纵坐标使用按原始行固定的 `P-000001` 编号，不因排序或分页改变；明细、提示与导出同时保留原始编号及行号。单项结局排序另保留，不再冒充综合预警。单人页不显示此人群预警榜。群体默认不自动请求首个人的SHAP/曲线，也不把任何个人图当成人群结论；个人明细必须主动选人查看。

综合相对预警算法版本为 `cohort_relative_midrank_v1`：先检查全文件已完成，对各共同可用结局在全部合格对象中计算并列平均名次（midrank），转为0–100百分位后等权合成。各对象使用同一组可用结局，不把缺失或被保护性隐藏的结局填零，也不因凑齐12项放宽可靠性保护；当前通常7/12项参与，另外5项保留未参与原因。至少5名合格对象、至少3项共同可用结局时才生成综合预警；不足时独立提示，不显示为绿色“无预警”。

默认阈值80分，可在页面调整；综合分达到阈值显示红色预警及真实“预警人数/已评估人数”占比，数据充分但无人达到显示绿色界面，未评估人数另列。显示分数保留1位小数，阈值判定使用原始精度。80/75只是可配置的产品演示和优先复核规则，不是公认临床阈值；该分数不是疾病概率、未来风险或重金属因果效应，未达阈值也不代表没有健康风险。切换单项结局不改变综合排序，报告与综合预警CSV使用相同算法、阈值及全量对象。

个人视图的原“毒物剂量-致病突变曲线”可展示铅输入响应，但明确不是致病阈值；原“风险推手与保护因素拆解”接带符号 SHAP，但明确不是因果作用。职业病概率、BKMR/PIP权重和铅×砷协同因缺少对应分类/因果模型及输入，原型图位保留并说明原因，不填写假百分比，不把模型覆盖率变成高危率，不用铅×镉冒充铅×砷。

群体页顶部展示整份原始文件的人数、合格/未纳入人数、性别、年龄、婚姻、学历等基础资料，缺失保留为未知；不只统计模型合格子集。下方展示综合预警、指标分布、多结局统计和未纳入原因，不再重复放置独立性别/年龄分层图卡。群体报告独立于任何个人dashboard，五章覆盖整文件统计与排序，支持全人×12结局、综合预警排序、所选结局全排序、12结局汇总及完整JSON下载。群体统计均为上传文件内的未加权描述，不是NHANES复杂抽样总体估计，也不是因果或临床诊断。

个人补充区保留逐人指标估计、有效数据覆盖率、绝对SHAP份额、输入敏感性曲线、多结局结果、铅×镉联合响应热图、带符号SHAP贡献。个人报告保留原六轴雷达图型，内容为绝对SHAP前五项及其余项的同尺度贡献份额，而不是不同单位浓度混画；各金属原单位数值另保留在补充区。模型选择中的其他独立原型保留但不可假执行。

个人明细图切换对象或结局后重新调用模型；改变源文件或输入立即使旧群体结果和报告失效。整群12结局已完成计算后，切换结局只重绘对应的全群体结果，不重跑全量模型。现有训练包中AST的原生解释为 `log(U/L)`，GGT为 `log1p(U/L)`，不能把各项贡献直接标成 U/L。非基本输入的模型缺失分支贡献也保留，不能为了显示三种金属而丢弃。

响应曲线与热图的网格仅为输入探索范围，不是安全阈值、参考区间或因果干预。固定NHANES J列的批量文件必须遵循列定义的单位，不能在弹窗把同一血铅数值重新标成 μg/L；单人明确同全血单位仍支持后端审计换算。
